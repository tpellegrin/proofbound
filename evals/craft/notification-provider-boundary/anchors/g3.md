## Domain alignment

Provider identity stays in the delivery layer where it belongs. `app.notify` merely passes the choice through; it does not inspect or act on it. Each provider (`acme.py`, implied `beacon.py`) owns its endpoint, authentication scheme, and payload mapping — the differences the task described. The `Notification` model is unchanged and remains ignorant of delivery mechanics. The retry policy and outcome vocabulary live in each provider's `deliver` function (duplicated, but intentionally so per the "everything specific lives here" convention), so the domain contract is preserved per provider.

## Change locality

The reach was proportionate: two existing files touched (`app.py`, `delivery/__init__.py`) plus one new provider module. The registry pattern absorbed the new provider without changes to `registry.py`, `model.py`, or `transport.py`. The only non-local aspect is the mandatory import in `delivery/__init__.py` — a consequence of Python's import-time registration. If more providers are added, that file will accumulate imports, but the alternative (auto-discovery) would add complexity disproportionate to the current scale.

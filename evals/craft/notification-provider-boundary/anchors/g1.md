## Composability

The change introduced a provider-selection concern into `app.py`, which previously knew nothing about delivery providers. The application layer now accepts and forwards a `provider` parameter, coupling callers to the delivery mechanism's plurality. `delivery/__init__.py` transformed from a thin delegation (`_sender.send`) into a registry-router (`_SENDERS[provider].send`), absorbing the knowledge of which providers exist and how to select them. Each sender class (`AcmeSender`, `BeaconSender`) gained a `provider` class attribute so the registry can index them — a small but real leakage of registry concerns into the implementations. The `Sender` protocol in `delivery/sender.py` was untouched, which is good: the contract remains stable.

## Domain alignment

The provider identity (`"acme"`, `"beacon"`) now lives in three places: as a default argument in `app.notify`, as a registry key in `delivery/__init__.py`, and as a class attribute on each sender. The sender class attribute is the most aligned — the sender *is* the authority on which provider it implements. The registry key in `delivery/__init__.py` is acceptable as wiring. The default in `app.notify` is less aligned: the application layer now expresses a delivery-infrastructure default (`"acme"`) that properly belongs to the delivery boundary. A future caller that doesn't care about providers still has to inherit that default or explicitly pass it.

## Change locality

The reach was proportionate. Four files changed: `app.py` (one parameter), `delivery/__init__.py` (registry + routing), `delivery/acme.py` (one class attribute), plus the new `delivery/beacon.py`. No changes to `notifications/model.py`, `transport.py`, or `delivery/sender.py`. The retry policy, outcome vocabulary, and transport seam remained entirely untouched — exactly as the acceptance criteria required. The only non-local aspect is the default provider string appearing in `app.py`, but that's a direct consequence of the API change requested (adding a fifth parameter with a default).
